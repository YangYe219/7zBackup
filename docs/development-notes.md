## 一、7z 命令行

### 1. 高强度加密的关键参数
```
7z a -t7z -mhe=on -mx=<0/5/9> -p<密码> -sccUTF-8 -y -- "输出.7z" "输入..."
```
- `-mhe=on`：**加密文件名/目录结构**，只对 7z 格式有效（zip 不支持）
- AES-256 是 7z 格式的默认算法，无需额外参数
- 压缩等级不影响加密强度，只影响体积/速度

### 2. 密码传参
- 密码直接拼在参数里，整体加引号：`"-p我的密码"`（含空格必须整体引住）
- **密码里不能有英文双引号**——会破坏命令行引号配对（程序里做了输入拦截）

### 3. 分卷 `-v`
- `-v2g` / `-v500m` / `-v100m`；生成 输出.7z.001 / .002 / …
- **坑：7z 不支持更新(追加)分卷压缩包**。所以分卷只能用于"一次 7z 调用
  能完成"的场景。本程序的规则：合并模式下若输入需要多次调用才压完，
  且选了分卷 → 直接提示不允许；批量模式下每个项目独立一次调用，没这个限制
- 校验/解压分卷包只需操作第一个 `.001`

### 4. 防止"把输出文件压进自己"
输出 .7z 落在某个被压缩的文件夹内部时，扫描会包含正在生成的压缩包。
解决：额外加排除开关 `-xr!输出文件名` 和 `-xr!输出文件名.0*`（分卷）。

### 5. 归档内不泄露本机绝对路径
- 设 `ProcessStartInfo.WorkingDirectory = 公共父目录`，参数里只传相对名
- 同一父目录的多个项目合并成一次调用；不同位置的项目逐项调用
  （不同目录的同名条目自动带上一层父文件夹名，避免归档内重名互覆）

### 6. 实时进度与中文输出
- 进度：逐行读 stdout，正则 `^\s*(\d{1,3})%\s*(.*)$`
- 中文文件名不乱码：加 `-sccUTF-8` 且 `StandardOutputEncoding = UTF8`
- stderr 必须另开线程读，否则缓冲区塞满会死锁
- 退出码语义：0 成功；**1 = 有警告（如个别文件被占用未打入）**；≥2 失败。
  备份场景 1 也要当问题提示，不能静默当成功

### 7. 密码快速验证（验证器的核心思路）
- 文件名加密的包：`7z l -slt -p密码` 能列出目录 ⇒ 密码正确（**秒级**）；
  列不出且报 Wrong password ⇒ 密码错误
- 文件名未加密的包（如普通 zip）：列目录成功不代表密码对，
  必须升级到 `7z t` 完整校验
- 判断包内是否有加密内容：`l -slt` 输出里找 `Encrypted = +`

### 8. 字典大小（实测 7-Zip 26.00）
- `l -slt` 里 `Method = LZMA2:NN` 的 **NN 是 2 的幂指数**（25→32MB、27→128MB）；
  非 2 的幂才显示 "24m"/"384k" 这类直读格式。用显式 `-md=16m/64m` 校准可解出
- 当前默认：**仅存储(-mx=0) 无字典；标准(-mx=5) 32MB；极限(-mx=9) 128MB**
- 小文件会自动缩字典（看到 LZMA2:384k 属正常）
- 解压端只需字典等量内存；压缩时约为字典的数倍

## 二、C# 与编译（零环境编译方案）

### 9. 用 Windows 自带编译器生成独立 exe
```
%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe
  /nologo /target:winexe /codepage:65001 /optimize+
  /out:程序.exe /r:System.dll /r:System.Core.dll
  /r:System.Drawing.dll /r:System.Windows.Forms.dll 源码.cs
```
- 任何 Win10/11 都能编译，不需要装 SDK
- 语法上限是 **C# 5**：没有 `$""` 插值、`?.`、`nameof`、模式匹配

### 10. 中文源码必须 `/codepage:65001`
csc 默认按系统 ANSI 代码页读源码，UTF-8 中文会变乱码/编译错误。
（或者给源码文件加 UTF-8 BOM。）

### 11. exe 被占用 → 先杀进程再编译
正在运行的程序会锁住 exe，报 CS0016"另一个程序正在使用此文件"。
`taskkill /IM 程序.exe /F` 后重编。

### 12. 大文件 SHA-256 带进度
不要用 `sha.ComputeHash(stream)`（一闷头算完），改分块：
`TransformBlock` 循环读 1MB 块，每 32MB 回调一次进度，最后
`TransformFinalBlock(buf,0,0)` 取 `sha.Hash`。

## 三、WinForms 界面（本项目最大的坑，最重要）

### 13. AutoScaleMode.Dpi 不可靠（根因）
现象：150% 缩放屏上中文文字挤出控件、复选框互相重叠，拖大窗口也没用。
原因：系统级 150% + 无清单的 winexe + P/Invoke SetProcessDPIAware 的组合下，
**字体按 1.5 倍渲染，但 AutoScaleMode.Dpi 没有缩放控件坐标**。
诊断：`HKCU\Control Panel\Desktop\WindowMetrics\AppliedDPI`（144=150%）。
**结论：别依赖 AutoScaleMode，手动缩放（见下）是确定性的。**

### 14. 手动 DPI 缩放的正确姿势
界面搭建完成后，一次性缩放：
```csharp
float f = 1f;
using (Graphics g = CreateGraphics()) f = g.DpiX / 96f;   // 150% 屏 = 1.5
```
- 遍历控件树：Location 乘 f；**AutoSize 控件跳过 Size**（文字自适配），
  其余 Size 乘 f；最后 ClientSize/MinimumSize 也乘 f
- 字体用 pt 单位（9F），会随 DPI 自动变大，与坐标缩放天然一致

### 15. 缩放时必须先摘掉锚定（第二坑）
直接缩放完改 ClientSize，**锚定布局会再算一次增量**：
底部/右下锚定的按钮被推出窗口外，四边锚定的 ListBox 被拉伸变形
（第一版修复后"下半屏消失"就是它）。
正确流程：
```
保存所有子控件的 Anchor → 全部临时置为 Top|Left
→ 缩放控件树 → 设置缩放后的 ClientSize/MinimumSize
→ 恢复各自的 Anchor
```
（Anchor 恢复时以控件当前bounds为基准，不会跳。）

### 16. 其他界面细节
- 中文 9pt 在 96dpi ≈ 12px/字，150% 下 18px/字——固定宽度标签按
  目标 DPI 预留，否则截断（"密码:"→"密"）
- ListView 单元格单独着色：`item.UseItemStyleForSubItems = false`
  （注意拼写是 SubItems）
- 密码框切换明文：`textBox.PasswordChar = '\0' 或 '●'`

## 四、自检（验证方法）设计

### 17. 自检要"真刀真枪"
`--selftest` 命令行模式（无界面，结果写日志文件），真实走一遍：
生成中文文件名/空文件夹/随机大文件 → 压缩 → **错误密码列目录必须失败**
（证明文件名加密）→ 正确密码解压**逐字节比对** → 相对路径检查 →
分卷 → 批量规划/打包 → 清单指纹与实际文件重算一致 → 垃圾文件确实被排除。
共 17 项，任何一项 FAIL 都能定位到具体功能。

### 18. 相对路径检查的陷阱
`7z l -slt` 输出里，`----------` 分隔线**之前**是归档自身信息块，
其中的 `Path = C:\...\Temp\...` 是归档文件自己的路径——
检查"是否泄露绝对路径"时要只看分隔线之后的条目区。

### 19. 7z 不一定装在 Program Files
本机装在 `C:\Apps\7-Zip`。查找顺序：
ProgramFiles / ProgramFiles(x86) → 注册表 `HKLM\SOFTWARE\7-Zip` 的 Path →
PATH 环境变量。全失败再提示安装。

### 20. 测试数据有讲究
中文文件名 + 嵌套 + 空文件夹 + **不可压缩的伪随机大文件**
（分卷测试需要体积够大；可压缩数据会全部塞进第一卷）。

## 五、环境与工具链

### 21. 沙箱 Bash 实际是 cmd
`ls/grep/find/head`、heredoc 全不可用；用 `dir /b`、`findstr`、
`tasklist|findstr`、PowerShell 包装复杂逻辑。中文路径/参数经 cmd 传递正常。

### 22. PowerShell 调用 exe 要用调用运算符
`& 'C:\路径\工具.exe' --selftest` —— 不加 `&` 时 `--` 会被解析成运算符报错。

### 23. 无 BOM 的 UTF-8 脚本
- 给 csc：加 `/codepage:65001` 即可
- 给 PowerShell 5.1：必须带 BOM，否则按 ANSI 读会乱码；
  技巧：脚本保持纯 ASCII，中文用 `[char]0x52A0` 这类码位拼接

### 24. 桌面快捷方式
WScript.Shell COM 对象创建 .lnk；目标路径从 $PSScriptRoot 取，
避免命令行传中文参数。
